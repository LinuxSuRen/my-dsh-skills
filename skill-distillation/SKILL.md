# 任务后技能沉淀

与 skill-refresh（按周期调研外部最佳实践保鲜）互补：本技能负责把**任务中积累的内部经验**固化为可复用技能。

## 1. 触发判定

任务完成后自检，满足任一即进入沉淀流程；都不满足则跳过，**避免技能膨胀**：

- **复杂**：跨多轮、多仓库、多服务协同，或方案经历推翻重来；
- **高难度**：排查许久的疑难问题（根因非显而易见）、首次引入的新技术栈或新领域；
- **耗时长**：远超同类任务常规时长的探索、踩坑与验证。

## 2. 提炼

只收**会改变 AI 执行行为的增量**：

- 踩坑与根因——尤其花了很久才定位的问题；
- 方案取舍与最终选择的原因；
- 可快速证伪的验证手段（命令、步骤）；
- 工具链用法与流程纪律。

不收：一次性细节、过程流水账、项目临时状态。

## 3. 分类

| 类别 | 判定标准 | 建议去处 |
|---|---|---|
| 通用技能 | 与具体项目无关，跨项目、跨技术栈可复用 | my-dsh-skills（个人技能库） |
| 项目级技能 | 依赖当前项目拓扑、构建命令、专属规范 | 项目仓库的 `.dsh/skills/` 或 `.agents/skills/` |

## 4. 提案与写入

- **先查重**：通用库与项目级技能目录是否已覆盖？已覆盖 → 生成修订提案；未覆盖 → 新建提案。
- 提案给出：`name`/`description`/`whenToUse`、正文规则、目标仓库；**研发确认后才动文件**。
- 写入遵循目标仓库的提交纪律：分支策略先问（独立新需求走 worktree）、git-identity 身份、PR 合入。
- 新增技能目录加入 my-dsh-skills 时，同步登记 askills 的 `embed.go` 嵌入清单。
- 技能正文保持**动作化**：写可执行的规则，不堆叙述。
