# 算法服务运维页设计模式

## 1. Redis 地址配置（连上才保存）

- 优先级：持久化文件（runtime/*.json）> env > 默认值
- 表单：地址输入框 + 保存按钮 + 连接状态（connected/disconnected + 最近错误）
- **连上才保存**：POST 先实测连通（PING），连上才写文件（坏地址 400 不落盘）
- 保存后提示"重启服务生效"（v1 不做热重连——Redis 客户端分散在多个启动期组件，热切换风险高）
- 配置文件优先于 env：忘记设 env 也能通过 UI 修正

## 2. 检测记录面板（环形缓冲 + 轮询）

- 内存环形缓冲（deque/切片 maxlen=100 + 锁），不落盘、重启清空
- 每条记录：时间、命令类型、request_id/来源、任务名、状态（成功/失败 badge）、耗时、结果摘要、错误详情（可展开）
- API：GET 列表（limit 可选 1-100）；不涉及权限码（服务本地工作台，非平台业务接口）
- UI：30s setInterval 轮询 + 手动刷新按钮；样式复用现有令牌体系

## 3. 令牌/授权状态三态展示

| 状态 | 含义 | 显示 |
|---|---|---|
| 未收到 auth.grant | 服务重启后平台未重发 | 尚未收到授权 |
| 有 token 无平台地址 | 令牌到了但地址缺失 | 已收到令牌但平台地址待定 |
| 已授权（token+地址） | 正常 | 已获平台授权（url） |

- auth.grant 到达时通过 WS/SSE 广播事件通知前端即时刷新（不走轮询）
- 断线时保留低频兜底轮询（如 30s），恢复后停止

## 4. 关键陷阱

- 测试 stub 必须忠实模拟真实平台的鉴权行为（如 /uploads 只认 cookie 不认 Bearer），否则测试绿但线上 401
- 双实例竞争消费：重启前先杀旧进程（心跳 30s 阈值内重启不会触发 offline→online 翻转，平台不会重发 grant）
- Go 的 Windows 端口占用错误是 WSAEADDRINUSE(10048) 而非 syscall.EADDRINUSE——只匹配后者则端口漂移在 Windows 不生效
