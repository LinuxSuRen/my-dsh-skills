# AI 代码变更评审门槛

研究基线：AI 使代码产出激增而人工 review 带宽不变（Meta RADAR）；AI 引入的问题约 22.7% 长期存活（SMU 实证）；用 AI 的人更自信但代码并不更安全（Stanford CCS'23）。本技能把"人类把控"落成两道机器可执行的闸门：完成前验证、合并前分级评审。

## 1. 完成门槛：证据先于断言

- 任何"已完成 / 已修复 / 测试通过 / 构建成功"的宣称，**必须附本条消息内新运行的验证命令与完整输出**；引用早先轮次的输出不算证据。
- 禁止推测性措辞：`should`、`probably`、`seems to`、`理论上`——不确定就再去运行。
- **不采信子 agent 的自述成功**：子代理报告的"测试通过"必须实跑复核（同命令再执行一次），与 subagent-parallel-dev 的独立复测纪律一致。
- 外生验证优于自我验证：验收信号必须来自生成代码的模型之外——编译、测试、静态分析、schema 校验、人工抽查；**生成代码的同一个模型自己拍板验收会退化为橡皮图章**。

## 2. 分级评审（review 任何 diff 先定级）

| 级别 | 判定 | 处理 |
|---|---|---|
| 🔴 CRITICAL | 安全缺陷（鉴权/加密/输入校验/密钥泄漏）、正确性错误、破坏性变更无版本化、数据丢失风险 | 阻止合并，立即修 |
| 🟡 IMPORTANT | 关键路径缺测试、明显性能退化（无界 O(n²)、N+1、大对象拷贝）、偏离既有架构模式、新依赖引入 | 修完或给出书面理由才可过 |
| 🟢 SUGGESTION | 可读性、命名、非功能优化、文档 | 记录，不阻塞 |

- 发现必须落到具体文件与行号，说明"为什么是问题、影响什么"，附修正建议而非只指出错误。
- 评审结论**落成 PR comment 或报告文件**——只在会话里说不算数，没有产物等于发现丢失。

## 3. 高风险清单：必须人工逐行

diff 触及以下区域时，不分体积大小一律升级人工逐行评审（AI 预审只能作为前置过滤，不能替代）：

1. **安全边界**：认证/鉴权/会话、加密与密钥处理、输入校验、权限判断（含快捷键等旁路入口）
2. **错误处理路径**：AI 最爱 fail-soft（吞错、空 catch、兜底返回默认值）——错误路径比 happy path 更要细看
3. **公共契约**：API 端点/字段、消息协议、事件结构、跨服务同名约定（时间戳格式、错误码）
4. **数据 schema 变更**：表结构、迁移脚本、序列化格式
5. **并发与资源**：goroutine/锁生命周期、连接与文件句柄释放、定时器清理
6. **新依赖引入**：说明用途、维护状态（最近 6 个月有无发布）、"<30 行能否自己实现"；20 行以内的任务禁止引依赖

## 4. 差分评审技术

- **只审 diff，不重读全库**：以 `git diff master...HEAD` 为界，评审范围与上下文由 diff 决定。
- **历史回归检查**：被改区域 `git log -L` / `git blame` 看一眼——是否重新引入历史上修过的 bug（回归类问题 AI 高发）。
- **爆炸半径**：统计被改函数/类型的调用方数量（`grep` 调用点即可）；调用方越多，评审深度越高。
- **无测试自动升级**：被改代码没有测试覆盖时，评审级别升一级（🟢→🟡，🟡→🔴）。
- **大 diff 拆批**：单 PR 超过约 400 行或跨 3 个以上关注点时，要求拆分后再审——大 diff 是 review 空心化的主因（多数 AI 生成 PR 收不到有效人类评审）。

## 5. 借口对照表（自我合理化即红旗）

| 借口 | 反驳 |
|---|---|
| "小 PR 不用细看" | 严重缺陷与 diff 体积无关 |
| "测试都过了" | 测试通过 ≠ 覆盖了这次改的路径；测试是 AI 自己写的更要问"测了什么" |
| "和上次那类改动一样" | 复制的代码复制了风险；上下文不同结论不同 |
| "以后再优化" | 登记进 AI 债务台账（见 ai-debt-ledger）才能"以后"，否则就是没有以后 |
| "agent 说它验证过了" | agent 的自述不是证据，实跑才是 |

## 6. 与既有技能的衔接

- 评审通过 ≠ 合并授权：合并权限始终属于研发，按 branching-workflow 执行（agent 只 review + comment）。
- 单测覆盖不了的跨仓库集成，按 subagent-parallel-dev 的真实服务 E2E 兜底。
- 大批量 AI 改动合并后，按 observability-design 建立前后对照指标（第三道闸门）。
